1. はじめての準備 (最初の 1 回だけ)

  1. 配布された setup.bat をダブルクリックします (置き場所はどこでも構いません)。
    → 必要なツール (Git / GitHub CLI / Python) の導入と mgtkit の取得が自動で行われます。
  2. 途中でブラウザが開いたら、画面の指示に従って GitHub にログインします (初回のみ)。
  3. マネージャーが起動すると、下の登録画面が表示されます。名前と自分の Claude API キーを入力して「登録してはじめる」を押します。

mgtkit 本体は C:\Users\(自分)\mgtkit に自動で取得されます。ここがバージョン管理の置き場所になるため、このフォルダを移動・改名しないでください (マネージャーの起動・更新・提出はすべてこの場所を前提に動きます)。開発せずにアプリを実行するだけなら、原則としてここで作業して OK です (ふだんの業務はこれだけで完結します)。もし機能追加の作業をするときは (まれなケースです)、このフォルダを直接いじらず、別の場所にコピーしてから作業してください (4 章のとおり、取得した版のコピーで作業します)。

参加申請は自動です — 初回起動時に「参加申請」が自動送信され、管理者が承認すると提出・承認に参加できるようになります (承認までの間も、起動・更新・β版の試用・フィードバックはそのまま使えます)。承認されたあとも特別な操作は不要で、マネージャーを起動するだけで参加が完了します。

初回起動時の登録画面 (実画面)。キーは自分の PC の中にだけ保存され、外部には送られません。
Claude API キー (sk-ant- で始まる文字列) は、提出時に「自動作成」を選んだときの説明文の作成と、検証失敗時の自動修正に「本人のキー」として使われます。どちらも本人が選んだ操作のときだけ使われ、黙って課金されることはありません (費用の目安は 4 章)。取得方法は巻末の付録を参照してください。

2. アプリを使う (起動タブ)

2 回目からは C:\Users\(自分)\mgtkit\manager\マネージャー起動.bat をダブルクリックするだけです。起動のたびにマネージャー自体も自動で最新の状態に更新されます。「起動」ボタンで mgtkit がブラウザで開きます。

画面の上のタブは、左から「起動」「β版の確認と承認」「更新版を提出」の 3 つです (使う回数の多いものから並べています)。この資料の 4 章はいちばん右のタブ、5 章はまん中のタブの話です。

起動タブ。いま使っている版とその更新内容が表示されます。「最新の状態です (時刻)」で確認状況が常に分かります。
タブの横の黄色い丸は「未対応の件数」です (起動 = 取り込み待ちの新しい版があるとき、β版の確認と承認 = 確認・承認待ちの提出の数)。更新完了などのお知らせは黄色いタグで表示されます (3 章) — 丸 = 件数、タグ = お知らせ、と覚えてください。

3. 最新版への更新は自動です

更新の操作は不要になりました。マネージャーが起動時と 10 分ごとの確認で新しい正式版を見つけると、自動で取り込み、起動タブに黄色いタグでお知らせします。承認がそろってから正式版が出来上がるまでの間は「新しい正式版を準備中です (数分かかります)。公開されると自動で更新されます。」のタグが出ます。

「過去の更新ログ」。だれがどの版を基に作り、いつ正式版になったかが図と一覧で分かります (日付が入るのは版が更新された日だけです)。「ZIP を保存」で過去版も取得できます。
  • アプリがまだ動いているときは、作業を壊さないよう自動では取り込みません。「更新版を使うときは、もう一度「起動」を押してください」の案内が出て、次の「起動」のときに 更新 → 起動 が行われます (ブラウザの画面を閉じてもアプリ本体はしばらく動いたままなので、そのときは「更新して開く / あとにする」の確認が出ます)。
  • 過去の更新ログ (起動タブのグレーのボタン): これまでの版を時系列の図と一覧で確認できます。図の横軸は日付で、版が更新された日にだけ薄い縦線と日付が入ります。グレーの太い線が正式版の並び、白い丸がそれぞれの版 (橙のリングが付いた丸がいま使っている版)、色のついた帯が提出された更新です (帯の中は「名前 #番号」で色は人ごと、点線はまだ確認中)。帯や丸を押すと、その版の更新内容が開きます。
  • 図の下の一覧は、上が「公開済み (新しい順)」、下が「確認と承認の途中 (まだ配れません)」です。「ZIP を保存」を押すと保存先をたずねる画面が出て、その版の配布 ZIP を保存できます (提出済みの計算書を当時の版で再現したいときに)。更新内容に出る「〜を基に作成」は提出時に記録された版です (記録が無い古い提出だけ「(推定)」が付きます)。

4. 更新版を提出する (更新版を提出タブ)

  1. マネージャーで取得した版 (version.json が入ったフォルダ) を基に改造します。
    場所: C:\Users\(自分)\AppData\Local\mgtkit\stable\mgtkit のコピーなど。
  2. 作業後、フォルダを丸ごと ZIP にします (右クリック → 圧縮)。
  3. 「ZIP を選んで提出」を押して、その ZIP を選びます。
  4. 確認画面 (「提出内容の確認」) で内容を確かめ、「更新内容」を Claude に書かせるか自分で書くかを選んで「提出する」を押します。
    更新内容と制限事項はこの確認画面で決まります。ここで決まった文章は、そのまま正式版のリリースノート (起動タブの「更新内容」) として全員に表示されます。制限事項には「使えない条件・エラーで止まるケース・未対応の機能」を書いてください。
更新版を提出タブ (実画面)。記入することはありません。更新内容の書き方は ZIP を選んだあとの確認画面で選びます。提出後の検証状況もこのタブで確認できます。

迷ったらフォルダ丸ごと ZIP で OK です。取得した版から変更したファイルだけが提出され、個人設定 (API キーなど)・計算結果 (mgtkit_out)・テストや開発用フォルダは自動で除外されます。実行ファイル (.exe .bat など) や PDF が ZIP に入っていてもエラーにはならず、更新情報としては読まれません (自動で除外されます)。API キー・アクセストークン・秘密鍵らしき文字列がコード内に紛れていた場合は、検出して提出をブロックします。パスワードらしき記述や必要ライブラリ (requirements.txt) の変更は、確認画面に注意として出るだけで、確認のうえ続けられます。

更新内容を誰が書くかを選ぶ

ZIP を選ぶと確認画面が出ます。ここで「更新内容」を Claude に書かせるか、自分で書くかを選びます。ここで決まった文章は、正式版になったときの「更新内容」としてそのまま全員に表示されます。

ZIP を選んだあとの確認画面 (実画面)。既定は「Claude で自動作成する」です。

自分で入力するを選ぶと、その場に記入欄が出ます (無料)。薄いグレーの文は記入例です (書き始めると消えます)。「更新内容」は空欄のままでは提出できません。制限事項は無ければ空欄で構いません。

「自分で入力する」を選んだところ (実画面)。

Claude で自動作成するを選んだ場合は、書き上がった文章が提出前に表示されます。おかしなところがあればその場で直せます。直してから「この内容で提出する」を押してください。

自動作成の結果を確認する画面 (実画面)。ここで「取り消す」を押せば、提出は行われません (何も送られません)。

提出後の流れ

提出すると自動で検証 (テスト・安全チェック) が行われ、エラーなく本体に組み込める状態になるとβ版として発行されます。

  • 検証で問題が出たら「自動修正を試す」を押すと、AI が原因を分析して修正を試みます (最大 3 回)。
  • 却下 (差し戻し) された場合は、修正した ZIP を選び、確認画面の「提出先」で「#○○ に修正版として積む」を選んで再提出します。
費用の目安: Claude API (本人のキー) が使われるのは、自分で選んだときだけです。
・確認画面で「Claude で自動作成する」を選んだとき — 1 回数十円程度 (変更の大きさで前後)
・検証失敗時に「自動修正を試す」を押したとき — 3 回まで動いた場合でおおむね 10〜20 万トークン・150〜300 円程度
確認画面で「自分で入力する」を選べば無料です。正式版のリリースノートは提出時の記入・自動作成の内容がそのまま使われるため、リリース時に追加の費用はかかりません。実際に使った量と料金は、画面右上の棒グラフのマークからいつでも確認できます (7 章)。

5. β版を確認して承認する (β版の確認と承認タブ)

検証を通過した提出は「β版」として発行され、このタブに提出ごとにまとまって表示されます。確認 → フィードバック → 承認までここで完結します。

  1. タブを開くと、確認・承認待ちの提出が自動で表示されます (承認 n/2 の黄色マーカー付き)。前回の内容をすぐ出したうえで、裏で最新に更新します。
  2. 「β版 〜 を試す」を押すと、普段の正式版とは別のフォルダ・別のデータ・別の画面で起動します (普段の作業には影響しません。画面上部にβ版バナーが表示されます)。
  3. 「フィードバック n 件」で、メンバーの感想・不具合報告を一覧できます。試した気づきもここから送信できます (承認の判断材料になります)。自分が書いたフィードバックは後から編集・削除できます。統合などでβ版が新しくなったあとは、前の版に寄せられたフィードバックが下に薄く残ります (件数は今のβ版あてのぶんだけです)。
  4. 「差分」を押すと、画面の中で詳細ビューワが開きます (次章参照)。
  5. 問題なければ「承認」、問題があれば「却下」(理由の入力が必須。提出者に伝わります)。もう一度押すと取り消せます (「承認を取り消す」「却下を取り消す」)。
  6. 2 人の承認がそろうと、自動で正式版としてリリースされ、全員に配布されます。リリースされた提出のβ版は一覧から自動で消えます (検証NG・却下・変更のぶつかり (統合待ち) があるあいだはリリースされません)。
β版の確認と承認タブ (実画面)。提出ごとに、β版の試用・フィードバック・承認状況・検証結果がひと目で分かります。
「フィードバック n 件」を押すと、誰が・いつ・どんな内容を送ったかが一覧でき、その場で自分のフィードバックも送信できます (実画面)。

自分の提出は自分では承認できません。また 1 人でも却下があるとリリースされません (修正版の再提出で解消します)。

提出の状態と操作

  • 提出者本人には「取り下げ」が表示されます。取り下げると提出とβ版は一覧から自動で消えます。
  • 却下が 2 人そろうと赤い「却下 2/2」の印と残り日数が付き、一覧のいちばん下の「却下が確定した提出 (自動で畳みました)」へ自動で畳まれます (3 日後に自動で片付きます)。「一覧に戻す」でグレー表示のカードに戻せ、却下した本人はそこから取り消せます。まだ確定していない提出も、カードの「非表示」で自分の画面からだけ畳めます。
  • 提出の後に正式版が進んで同じ箇所の変更がぶつかった場合は「統合待ち」になり、承認・却下はいったん止まります。提出者が「最新版と統合」を押すと解消され、承認は仕切り直しになるので改めて確認してください。

6. 差分ビューワ — 変更内容をくわしく確認する

「差分」を押すと、マネージャーの画面の中に詳細ビューワが開きます (別のアプリに移らずそのまま確認できます)。

  • 〈1〉フォルダ比較 — 変更されたファイルの一覧。提出時に「Claude で自動作成する」を選んだ提出では、各ファイルに「何のためにどんな機能を加えたか」の説明が付きます (「自分で入力する」を選んだ提出では説明なしの一覧になります)。ファイル名を押すと、その場所へ移動します。
  • 〈2〉ファイル比較 — 変更前 (左) と変更後 (右) を並べて表示。赤 = 変更前、緑 = 変更後・追加、紺 = 削除された行。変更のない行は折りたたまれます。変更がとても多いファイルは「この差分を表示」を押したときに開きます (開くのを速くするため)。

下の「ブラウザで開く」を押すと、同じ内容をいつものブラウザでも開けます。次のことをしたいときはこちらが便利です。

  • コードを選択してコピーする
  • Ctrl+F で検索する (目当ての行を探す)
  • 印刷・PDF 保存する
差分ビューワをブラウザで開いたところ。マネージャーの画面の中でも同じ内容が見られます。ファイルごとの説明 (青枠) は「自動作成」を選んだ提出に付きます (提出時に作られた説明のため、その後の自動修正や統合の内容は含みません)。

「確認用データを保存...」(ブラウザでは右上の「⬇ β版データ (確認用) をダウンロード」) から、確認用データ (#N_確認用.zip) を取得できます。中身は「一式」(そのまま動作チェックに使えるβ版まるごと) と「変更のみ」(変更されたファイルだけ。中身チェック用) です。保存の前に、資料「バージョン管理と同時開発のしくみ」4.2 の 3 つのリスクを確認する画面が出ます。取得したデータは動作チェック・中身チェック用です。機能追加の作業は、これまでどおりマネージャーで取得した版のコピーで行ってください。

7. API の利用量を確認する

画面右上の棒グラフのマークを押すと、このマネージャー経由で使った Claude API の利用量と料金の目安が確認できます (月の小計 → 直近 30 日のグラフ → 日ごとの利用料 → 通算合計)。

API 利用量の画面 (実画面)。表示されるのはこの PC のマネージャー経由分のみの「目安」です。

付録. Claude API キーの取得方法

マネージャーの初回登録で入力する Claude API キー (sk-ant- で始まる文字列) は、Anthropic の開発者向け管理画面「Claude Console」で発行します。手順は 4 ステップです。

  1. Claude Console にアクセス — ブラウザで https://console.anthropic.com を開き、Anthropic アカウントでログインします (初回はアカウント作成と支払い設定が必要です。API の利用料は claude.ai の Pro / Max プランとは別の従量課金です)。
  2. 左メニューの「API キー」を選択します。
  3. 右上の「＋ キーを作成」をクリックします。
  4. 名前と有効期限を付けて発行します — 名前は mgtkit など用途が分かるもの、有効期限は 1 か月程度が無難です (長期間有効なキーは漏えい時のリスクが大きくなります)。

Claude Console は Anthropic の画面で、この資料では図を載せていません (実物と食い違う絵を載せないため)。画面の文言が変わっていても、「API キー」→「キーを作成」の流れは同じです。

発行されたキーは発行直後の画面でしか表示されません。その場でコピーして、マネージャーの初回登録画面に貼り付けてください。キーは自分の PC 内にのみ保存され、提出データには含まれません。

期限が切れたとき (キーの再登録): 同じ手順で新しいキーを発行し、C:\Users\(自分)\AppData\Local\mgtkit\settings.json を削除してからマネージャーを起動し直すと、登録画面が再表示されるので新しいキーを入力してください。
