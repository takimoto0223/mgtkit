1. はじめての準備 (最初の 1 回だけ)

  1. 配布された setup.bat をダブルクリックします (置き場所はどこでも構いません)。
    → 必要なツール (Git / GitHub CLI / Python) の導入と mgtkit の取得が自動で行われます。
  2. 途中でブラウザが開いたら、画面の指示に従って GitHub にログインします (初回のみ)。
  3. マネージャーが起動すると、下の登録画面が表示されます。名前と自分の Claude API キーを入力して「登録してはじめる」を押します。

mgtkit 本体は C:\Users\(自分)\mgtkit に自動で取得されます。ここがバージョン管理の置き場所になるため、このフォルダを移動・改名しないでください (マネージャーの起動・更新・提出はすべてこの場所を前提に動きます)。開発せずにアプリを実行するだけなら、原則としてここで作業して OK です (ふだんの業務はこれだけで完結します)。もし機能追加の作業をするときは (まれなケースです)、このフォルダを直接いじらず、別の場所にコピーしてから作業してください (4 章のとおり、取得した版のコピーで作業します)。

参加申請は自動です — 初回起動時に「参加申請」が自動送信され、管理者が承認すると提出・承認に参加できるようになります (承認までの間も、起動・更新・β版の試用・フィードバックはそのまま使えます)。承認されたあとも特別な操作は不要で、マネージャーを起動するだけで参加が完了します。

はじめに登録してください

mgtkit マネージャーの利用には、名前と本人の Claude API キーの登録が必要です。

キーはこの PC の中にだけ保存され、提出時に「自動作成」を選んだときと、検証失敗時の自動修正に本人のキーとして使われます。

3. 最新版への更新は自動です

更新の操作は不要になりました。マネージャーが起動時と 10 分ごとの確認で新しい正式版を見つけると、自動で取り込み、起動タブに黄色いタグでお知らせします。

アプリを v1.2 に更新しました。このまま「起動」してお使いいただけます。
更新が済むと起動タブに黄色いタグが出ます。一度起動すると畳まれます。
  • アプリの画面を開いたままのときは、作業を壊さないよう自動では取り込みません。「アプリを閉じてから起動し直すと更新されます」の案内が出て、次の「起動」のときに 更新 → 起動 が行われます (使用中に「起動」を押した場合は「更新して開く / あとにする」の確認が出ます)。
  • 過去の更新ログ (起動タブのグレーのボタン): これまでの版の日付・提出者・更新内容を時系列の図と一覧で確認できます。「ZIP を保存」でその版の配布 ZIP をダウンロードフォルダに保存できます (提出済みの計算書を当時の版で再現したいときに)。

4. 更新版を提出する (更新版を提出タブ)

  1. マネージャーで取得した版 (version.json が入ったフォルダ) を基に改造します。
    場所: C:\Users\(自分)\AppData\Local\mgtkit\stable\mgtkit のコピーなど。
  2. 「更新内容」と「ご利用にあたっての制限事項」を記入します (薄いグレーの例のように書きます)。
    ここに書いた内容は、そのまま正式版のリリースノート (起動タブの「更新内容」) として全員に表示されます。制限事項には「使えない条件・エラーで止まるケース・未対応の機能」を書いてください。
  3. 作業後、フォルダを丸ごと ZIP にします (右クリック → 圧縮)。
  4. 「ZIP を選んで提出」→ 確認画面で内容をチェック → 提出。

迷ったらフォルダ丸ごと ZIP で OK です。取得した版から変更したファイルだけが提出され、個人設定 (API キーなど)・計算結果 (mgtkit_out)・テストや開発用フォルダは自動で除外されます。実行ファイル (.exe .bat など) や PDF が ZIP に入っていてもエラーにはならず、更新情報としては読まれません (自動で除外されます)。万一 API キーの文字列がコード内に紛れていた場合のみ、検出して提出をブロックします。

提出後の流れ

提出すると自動で検証 (テスト・安全チェック) が行われ、エラーなく本体に組み込める状態になるとβ版として発行されます。

  • 検証で問題が出たら「自動修正を試す」を押すと、AI が原因を分析して修正を試みます (最大 3 回)。
  • 却下 (差し戻し) された場合は、修正した ZIP を「同じ提出に修正版として積む」を選んで再提出します。
費用の目安: Claude API (本人のキー) が使われるのは、自分で選んだときだけです。
・提出の説明の「自動作成」を選んだとき — 1 回数十円程度 (変更の大きさで前後)
・検証失敗時に「自動修正を試す」を押したとき — 3 回まで動いた場合でおおむね 10〜20 万トークン・150〜300 円程度
説明を自分で記入して提出すれば無料です。正式版のリリースノートは提出時の記入・自動作成の内容がそのまま使われるため、リリース時に追加の費用はかかりません。実際に使った量と料金は、画面右上の棒グラフのマークからいつでも確認できます (7 章)。

5. β版を確認して承認する (β版の確認と承認タブ)

検証を通過した提出は「β版」として発行され、このタブに提出ごとにまとまって表示されます。確認 → フィードバック → 承認までここで完結します。

  1. 「一覧を取得」で、確認・承認待ちの提出が表示されます (承認 n/2 の黄色マーカー付き)。
  2. 「β版 〜 を試す」を押すと、普段の正式版とは別のフォルダ・別のデータ・別の画面で起動します (普段の作業には影響しません。画面上部にβ版バナーが表示されます)。
  3. 「フィードバック n 件」で、メンバーの感想・不具合報告を一覧できます。試した気づきもここから送信できます (承認の判断材料になります)。自分が書いたフィードバックは後から編集・削除できます。
  4. 「差分」を押すと、ブラウザで詳細ビューワが開きます (次章参照)。
  5. 問題なければ「承認」、問題があれば「却下」(理由の入力が必須。提出者に伝わります)。もう一度押すと取り消せます (「承認を取り消す」「却下を取り消す」)。
  6. 2 人の承認がそろうと、ロケットが発射して自動で正式版としてリリースされ、全員に配布されます。リリースされた提出のβ版は一覧から自動で消えます (検証NG・却下・変更のぶつかり (統合待ち) があるあいだは発射されません)。

β版の確認と承認タブ。提出ごとに、β版の試用・フィードバック・承認状況・検証結果がひと目で分かります。

承認・却下の進み具合はカード右上のロケットでも表現されます — 承認 1 つで点火 🔥 (発射準備)、2 つで発射 🚀 (自動リリース)、却下 1 つで煙 💨、却下が 2 つそろうと転倒・爆発 💥 して一覧下の「非表示」へ自動で移動します (「一覧に戻す」で表示に戻せます)。

自分の提出は自分では承認できません。また 1 人でも却下があるとリリースされません (修正版の再提出で解消します)。

提出の状態と操作

  • 提出者本人には「取り下げ」が表示されます。取り下げると提出とβ版は一覧から自動で消えます。
  • 却下が 2 人そろうと「却下確定」になり、爆発演出のあと一覧下の「非表示」へ自動で移動し、3 日後に自動で片付きます (「一覧に戻す」でグレー表示のカードに戻せます。却下の取り消しもそこから可能です)。
  • 提出の後に正式版が進んで同じ箇所の変更がぶつかった場合は「統合待ち」になり、承認・却下はいったん止まります。提出者が「最新版と統合」を押すと解消され、承認は仕切り直しになるので改めて確認してください。

6. 差分ビューワ — 変更内容をくわしく確認する

「差分」を押すと、いつものブラウザで詳細ビューワが開きます。

  • 〈1〉フォルダ比較 — 変更されたファイルの一覧。提出時に「自動作成」を選んだ提出では、各ファイルに「何のためにどんな機能を加えたか」の説明が付きます (空欄・手書きの提出では説明なしの一覧になります)。
  • 〈2〉ファイル比較 — 変更前 (左) と変更後 (右) を並べて表示。赤 = 変更前、緑 = 変更後・追加、紺 = 削除された行。変更のない行は折りたたまれます。

付録. Claude API キーの取得方法

マネージャーの初回登録で入力する Claude API キー (sk-ant- で始まる文字列) は、Anthropic の開発者向け管理画面「Claude Console」で発行します。手順は 4 ステップです。

  1. Claude Console にアクセス — ブラウザで https://console.anthropic.com を開き、Anthropic アカウントでログインします (初回はアカウント作成と支払い設定が必要です。API の利用料は claude.ai の Pro / Max プランとは別の従量課金です)。
  2. 左メニューの「API キー」を選択します。
  3. 右上の「＋ キーを作成」をクリックします。
  4. 名前と有効期限を付けて発行します — 名前は mgtkit など用途が分かるもの、有効期限は 1 か月程度が無難です (長期間有効なキーは漏えい時のリスクが大きくなります)。
