# 図の作法: 線で関係・順番を結ぶ図 (全プロジェクト共通)
対象は、箱や帯を線・矢印で結ぶ図すべて。ガント、更新ログ (mgtkit の historyview)、組織図・構成図 (archify-diagram)、フロー図。
建築の構造図は対象外で、正本は str-works の docs/構造図の記法.md。
1. **線は消さずに形で直す**。依存・順番・報告の線は図の中身。描き方が崩れたら描き方を直し、データ (after: など) を落として逃げない。
   落としてよいのは、指す先が無い線だけ。そのときは警告を出す
2. **位置は描く座標 (px) で決める**。重なるか、線が届くかを、日付などの意味の座標で判定しない。要る幅・高さは先に確保し、
   足りなければ図を縦にも横にも伸ばす
3. **線は縦横と丸い角で描く**。始点の箱の辺から縦に出て、角を円弧で丸め、終点の箱の入口 (左) へ横から入る。逆向き (後の箱が上)
   も同じ形にし、箱を突き抜ける斜めの線にしない。縦の線を引く場所が無ければ、箱の間の溝を回り込む
4. **線と矢先はなめらかにつなぐ**。円弧は取れる幅を超えて描かない (矢先を追い越さない)。線の終点と矢先の根元を一致させる
5. **交差は Ω で跨ぐ** (ライン ジャンプ)。Ω の字を描くのではない。横の線が縦の線を横切る所で、横の線に上へ膨らむ小さな半円
   (半径 4px) を入れ、縦の線は切らずに真っ直ぐ通す。つながっていない交差だと一目で分かるようにするため。
   SVG なら `L (cx−4) y A 4 4 0 0 sweep (cx+4) y` (右向きは sweep=1、左向きは 0 で、どちらも上に膨らむ)。
   つながる所 (合流・分岐) は点か箱で示し、山は描かない。跨ぐのは線どうしだけで、目盛り・今日の線・背景の帯は跨がない
6. **確かめ方**: 数値で言えること (重ならない・終点と矢先の根元が一致・交差に山がある) は座標の検査としてテストにする。
   目で見るのは最後の答え合わせ (SVG に写すかスクリーンショットで)
