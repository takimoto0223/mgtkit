# フォルダ構成の切り替え — 配布前の試験手順 (管理者用)

メンバーに配る前に、**自分の PC だけで**引っ越しを通しで確かめるための
手順。旧環境はそのまま動かしたままにできるので、失敗しても業務は止まらない。

判断の背景は `decisions.md` の「フォルダ構成の切り替え — 実装」を参照。

## 大前提

`マネージャー起動.bat` は起動のたびに `git pull` する。つまり
**main に入れた瞬間に全員の PC へ届く**。裏返せば、**ブランチに置いてある
限り誰にも届かない**。試験はブランチを指定して行う。

## 用意するもの

作業ブランチから次の 2 つを、デスクトップなどの空フォルダに保存する
(GitHub のブランチのページから「Raw」→ 名前を付けて保存)。

- `manager/scripts/setup.bat`
- `manager/scripts/setup-test.bat`

**いま使っているクローン (`C:\Users\(自分)\mgtkit`) は触らない。**
ブランチに切り替えると、ふだんのマネージャーが試験中のコードで動いて
しまう。

---

## 段階 1 — 下見 (どこにも書き込まない)

引っ越しが**何をどこへ運ぶか**だけを表示する。旧フォルダにも `C:\` にも
一切触らない。

```
cd $env:USERPROFILE\Desktop
git clone -b <ブランチ名> https://github.com/takimoto0223/mgtkit.git mgtkit-dryrun
cd mgtkit-dryrun
py -3 -m manager.migrate --dry-run
```

> PowerShell 前提で書いてある。コマンドプロンプト (cmd) を使うときは
> 1 行目を `cd %USERPROFILE%\Desktop` にする
> (PowerShell は `%VAR%` を展開しない)。

出力の例:

```
--- 下見 (dry-run): 実際には何も書き換えません ---
置き場所: C:\mgtkit_appmanager
見つかったこれまでのフォルダ:
  C:\Users\(自分)\mgtkit
  C:\Users\(自分)\AppData\Local\mgtkit
引き継ぎます:
  運びます: お名前と API キー
  運びます: API の利用量
  運びます: この PC の表示の記録
  運びます: いま入っている正式版
  運びます: 読み込んだファイルの一時置き場
  運びます: 直接なおした内容の退避先
片付けを予約します (実際に消すのは次回の起動時): C:\Users\... 、C:\Users\...
--- 下見はここまで。何も書き換えていません ---
```

**「読み込んだファイルの一時置き場」が出ないことがあるが正常。** アプリの
一時フォルダはブラウザからファイルをアップロードしたときに初めて作られる
(`app.py` の `os.makedirs(_UPLOAD_DIR)`)。移行元に無いものは飛ばす。
同じく「直接なおした内容の退避先」は、クローン内を直接編集して退避された
ことがある人にだけ出る。

見終わったらデスクトップの `mgtkit-dryrun` を消す (下見用のクローンなので、
これだけがディスクに残る。約 20MB)。

> `setup-test.bat <ブランチ名> --dry-run` でも下見はできるが、そちらは
> **先に試験用フォルダへ clone してから**下見をするので「どこにも
> 書き込まない」にはならない。純粋な下見は上のやり方で行う。

## 段階 2 — 本番と別の場所に作ってみる

```
.\setup-test.bat <ブランチ名>
```

`C:\mgtkit_appmanager_test\` に一式ができる。**旧フォルダは読むだけで
消えない**し、片付けの予約 (札) も置かれない。

確認すること:

| # | 見るところ | 期待 |
|---|---|---|
| 1 | `C:\` に新しいフォルダができたか | 権限で弾かれない |
| 2 | `.manager` が見えないか | 隠しファイルの表示を切ると消える |
| 3 | 一番上に入口 (`mgtkit アプリマネージャー`) があるか | `.lnk` か、無理なら中継バッチ |
| 4 | 入口をダブルクリック | マネージャーが開く |
| 5 | 開いた画面 | **登録画面 (名前と API キー) が出ない**。出なければ settings.json が読めている (`main.py` は読めなかったときだけ登録画面を出す)。名前そのものは画面に表示されない |
| 6 | API 利用量 | これまでの金額が出る |
| 7 | 「起動」 | アプリがブラウザで開く |
| 8 | 「β版を試す」 | β版が別画面で開く |
| 9 | 「更新版を提出」 | 差分が出る (workrepo が作り直される) |
| 10 | 一番上の使い方ガイド PDF | 開ける |

入口をデスクトップにコピーして、そこからも開けることも確認する。

**戻し方**: `C:\mgtkit_appmanager_test` を消すだけ。旧環境はそのまま。

> 注意: 試験用のマネージャーと、ふだんのマネージャーを**同時に起動しない**
> こと。アプリのポート (8765 / 8766) を取り合う。

## 段階 3 — 本番の場所で、片付けだけ保留して使ってみる

```
$env:MGTKIT_HOME = "C:\mgtkit_appmanager"
$env:MGTKIT_BRANCH = "<ブランチ名>"
$env:MGTKIT_MIGRATE_OPTS = "--no-cleanup"
.\setup.bat
```

> cmd のときは `set "MGTKIT_HOME=C:\mgtkit_appmanager"` の書き方にする。

本番の置き場所に作るが、**旧フォルダは消さない**。数日これを使ってみる。

戻したくなったら `C:\mgtkit_appmanager` を消し、これまでどおり
`C:\Users\(自分)\mgtkit\manager\マネージャー起動.bat` から起動する。

## 段階 4 — 後片付けまで通す

念のため `C:\Users\(自分)\mgtkit` と
`C:\Users\(自分)\AppData\Local\mgtkit` を ZIP で退避してから、
`--no-cleanup` を外して実行する (= 本番と同じ手順)。

```
setup-test.bat <ブランチ名>   ではなく、ブランチ指定だけした setup.bat
```

**`setup.bat` が終わった時点で旧フォルダは消えている。** 確認:

```
Test-Path $env:USERPROFILE\mgtkit, $env:LOCALAPPDATA\mgtkit
Test-Path C:\mgtkit_appmanager\.manager\cleanup_pending.json
```

期待: `False` `False` と `False` (札が無い = 全部消えた)。

札が `True` のときは、使用中などで消しきれなかったフォルダがある。
**マネージャーを開き直せば消し直す** (5 回試して駄目なら画面に「手で消して
ください」と出る)。

引っ越しのときに**これまでのアプリは自動で終了される** (8765 / 8766)。
止めないと、アプリが作業フォルダにしている `stable\mgtkit` と
`beta\<版>\mgtkit` が消せず、空のフォルダが残る。

消えなかった場合は次の起動で再試行される (5 回試して駄目なら画面に
「手で消してください」と出る)。

## 途中で失敗したときの確かめ

引っ越しの途中で強制終了しても、**もう一度 setup.bat を実行すれば続きから
進む**ようにしてある。段階 2 の途中でウィンドウを閉じ、もう一度実行して
最後まで通ることを一度は見ておくとよい。

## 新規導入の経路も見るなら

Windows のアカウントをもう 1 つ作り、旧フォルダが無い状態から同じ
`setup.bat` を実行する。「これまでのフォルダは見つかりませんでした
(新規の導入として続けます)」と出て、入口とガイドだけが作られる。

## ブランチで試したあとは

試験用に `MGTKIT_BRANCH` を指定して作った環境は、そのブランチを追い続ける。
main へマージしたあとに戻すこと:

```
git -C C:\mgtkit_appmanager\.manager\mgtkit checkout main
git -C C:\mgtkit_appmanager\.manager\mgtkit pull --ff-only
```

> **この 2 行は続けて実行し、その間にマネージャーを起動しないこと。**
> `checkout` した直後はマージ前の版になっているので、そこで起動すると
> 旧構成の想定で動き、消えた旧フォルダを見にいって登録画面が出る。

## 全部通ったら

ブランチを main へマージする。次に各メンバーが起動したときに新しい
コードは届くが、**移行していない PC はこれまでの配置のまま動く**
(配置はクローンの居場所だけで決まるため)。あとは新しい `setup.bat` を
配って、各自に一度だけ実行してもらう。
