# フォルダ構成の切り替え — 配布前の試験手順 (管理者用)

メンバーに配る前に、**自分の PC だけで**引っ越しを通しで確かめるための
手順。旧環境はそのまま動かしたままにできるので、失敗しても業務は止まらない。

判断の背景は `decisions.md` の「フォルダ構成の切り替え — 実装」を参照。

## 大前提

`マネージャー起動.bat` は起動のたびに `git pull` する。つまり
**main に入れた瞬間に全員の PC へ届く**。裏返せば、**ブランチに置いてある
限り誰にも届かない**。試験はブランチを指定して行う。

## 用意するもの

作業ブランチから次の 2 つを、デスクトップなどの空フォルダに保存する
(GitHub のブランチのページから「Raw」→ 名前を付けて保存)。

- `manager/scripts/setup.bat`
- `manager/scripts/setup-test.bat`

**いま使っているクローン (`C:\Users\(自分)\mgtkit`) は触らない。**
ブランチに切り替えると、ふだんのマネージャーが試験中のコードで動いて
しまう。

---

## 段階 1 — 何をするかだけ見る (書き換えなし)

```
setup-test.bat <ブランチ名> --dry-run
```

引っ越しで何をどこへ運ぶかが表示されるだけで、**1 バイトも書き換えない**。
運ぶ一覧に次が出ていることを確認する。

- お名前と API キー
- API の利用量
- いま入っている正式版
- 読み込んだファイルの一時置き場
- 直接なおした内容の退避先 (stash を作ったことがある場合のみ)

## 段階 2 — 本番と別の場所に作ってみる

```
setup-test.bat <ブランチ名>
```

`C:\mgtkit_appmanager_test\` に一式ができる。**旧フォルダは読むだけで
消えない**し、片付けの予約 (札) も置かれない。

確認すること:

| # | 見るところ | 期待 |
|---|---|---|
| 1 | `C:\` に新しいフォルダができたか | 権限で弾かれない |
| 2 | `.manager` が見えないか | 隠しファイルの表示を切ると消える |
| 3 | 一番上に入口 (`mgtkit アプリマネージャー`) があるか | `.lnk` か、無理なら中継バッチ |
| 4 | 入口をダブルクリック | マネージャーが開く |
| 5 | 画面右上の名前 | 自分の名前が出る (再入力を求められない) |
| 6 | API 利用量 | これまでの金額が出る |
| 7 | 「起動」 | アプリがブラウザで開く |
| 8 | 「β版を試す」 | β版が別画面で開く |
| 9 | 「更新版を提出」 | 差分が出る (workrepo が作り直される) |
| 10 | 一番上の使い方ガイド PDF | 開ける |

入口をデスクトップにコピーして、そこからも開けることも確認する。

**戻し方**: `C:\mgtkit_appmanager_test` を消すだけ。旧環境はそのまま。

> 注意: 試験用のマネージャーと、ふだんのマネージャーを**同時に起動しない**
> こと。アプリのポート (8765 / 8766) を取り合う。

## 段階 3 — 本番の場所で、片付けだけ保留して使ってみる

```
set "MGTKIT_HOME=C:\mgtkit_appmanager"
set "MGTKIT_BRANCH=<ブランチ名>"
set "MGTKIT_MIGRATE_OPTS=--no-cleanup"
setup.bat
```

本番の置き場所に作るが、**旧フォルダは消さない**。数日これを使ってみる。

戻したくなったら `C:\mgtkit_appmanager` を消し、これまでどおり
`C:\Users\(自分)\mgtkit\manager\マネージャー起動.bat` から起動する。

## 段階 4 — 後片付けまで通す

念のため `C:\Users\(自分)\mgtkit` と
`C:\Users\(自分)\AppData\Local\mgtkit` を ZIP で退避してから、
`--no-cleanup` を外して実行する (= 本番と同じ手順)。

```
setup-test.bat <ブランチ名>   ではなく、ブランチ指定だけした setup.bat
```

引っ越しの直後は**まだ消えない**。片付けの札が置かれ、**次にマネージャーを
起動したときに**旧フォルダが消える。1 回起動し直して、2 つのフォルダが
消えていることを確認する。

消えなかった場合は次の起動で再試行される (5 回試して駄目なら画面に
「手で消してください」と出る)。

## 途中で失敗したときの確かめ

引っ越しの途中で強制終了しても、**もう一度 setup.bat を実行すれば続きから
進む**ようにしてある。段階 2 の途中でウィンドウを閉じ、もう一度実行して
最後まで通ることを一度は見ておくとよい。

## 新規導入の経路も見るなら

Windows のアカウントをもう 1 つ作り、旧フォルダが無い状態から同じ
`setup.bat` を実行する。「これまでのフォルダは見つかりませんでした
(新規の導入として続けます)」と出て、入口とガイドだけが作られる。

## 全部通ったら

ブランチを main へマージする。次に各メンバーが起動したときに新しい
コードは届くが、**移行していない PC はこれまでの配置のまま動く**
(配置はクローンの居場所だけで決まるため)。あとは新しい `setup.bat` を
配って、各自に一度だけ実行してもらう。
